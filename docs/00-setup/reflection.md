# 1.5. Рефлексия

## 1. Границы системы и внешнее окружение

В моей системе «Служба такси» системой являются: сервер заказов, сервис подбора водителей, сервис динамического ценообразования, база данных поездок и мобильное приложение. Внешним окружением я считаю клиента, водителя, платёжный шлюз и внешний геосервис (карты). Они находятся за пределами системы и взаимодействуют с ней через API — это внешние акторы.

## 2. Три наиболее полезные диаграммы UML

Самые полезные диаграммы
- **Use Case** — лучше всего показывает, кто и какие функции использует: клиент заказывает и отменяет поездку, водитель принимает заказ, диспетчер разрешает спор. Без нее невозможно согласовать объем работ с заказчиком.
- **Sequence** — она детально описывает сценарий поездки: адреса — расчёт — подбор водителя — подтверждение. Это ключевой бизнес-процесс, и его нужно задокументировать.
- **Activity** — она моделирует логику отмены поездки с ветвлениями (штраф / без штрафа), что важно для корректной реализации правил биллинга.

## 3. Проблемы с PlantUML и их решение

При раскладке диаграмм Use Case PlantUML разместил акторов и варианты использования не так, как я хотела: клиент оказался справа, а не слева, а некоторые use case пересекались линиями. Кроме того, длинные русские подписи переносились некрасиво, ломая компоновку.

Я обошел это через директиву `left to right direction` для горизонтальной раскладки, ручное задание порядка через `together` и разбиение длинных подписей на две строки символом `\n`. Также помогло `skinparam rectangle` включить `<b>`. `--так` стал компактнее, и линии перестали пересекаться.
